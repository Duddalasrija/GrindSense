# Simulated telemetry data dictionary

Each record returned by `GET /api/sessions/{sid}/telemetry` contains one generated reading and a timestamp. `GET /api/sessions/{sid}/results` embeds the same telemetry shape. Values are generated by `backend/app/simulation.py`; there is no sensor acquisition.

| Field | Representation / UI unit | Generation and range notes | Interpretation limit |
|---|---|---|---|
| `timestamp` | ISO-formatted datetime | Assigned when the telemetry record is persisted. | Software event time; not a synchronized instrument timestamp. |
| `motor_current` | Numeric; UI displays A | Generated from simulated load with deterministic variation. No physical calibration or validated range is defined. | Not a current sensor reading or electrical characterization. |
| `motor_load` | Numeric; UI displays % | Generated from task/ingredient factors, intensity, tick, scenario, and deterministic variation; bounded by the generator to 8–110. | Software load estimate, not measured motor load. |
| `temperature` | Numeric; UI displays °C | Generated from tick, intensity, load, and scenario. No generator clamp or validated range is defined. | Not a temperature sensor reading or ingredient/jar temperature. |
| `vibration` | Numeric; UI displays mm/s | Generated from tick and simulated load; high-vibration scenario can raise it. No generator clamp or validated range is defined. | Not accelerometer data or measured vibration. |
| `acoustic_signature_index` | Numeric unitless index | Derived from simulated load, vibration, intensity, optional high-acoustic scenario contribution, and deterministic variation; bounded to 0–120. | Unitless simulated proxy; not microphone readings, sound pressure, or measured acoustic signature. |
| `torque_demand_index` | Numeric unitless index | Derived from simulated load × intensity; bounded to 0–100. | Unitless simulated proxy; not measured physical torque or torque demand. |
| `motor_speed` | Numeric; UI displays RPM | Derived from virtual speed setting × intensity with deterministic variation and a lower bound of 300. No upper bound is specified in the generator. | Not tachometer data or actual motor speed. |
| `texture_index` | Numeric index, UI presents out of 100 | Computed from simulated progress, smoothness setting, and ingredient factor; bounded to 0–100. | Estimated software index, not particle-size or texture measurement. |
| `progress` | Numeric percent-like scale | Accumulates a simulated per-tick increment and is bounded to 0–100. | Software progression signal, not measured grinding completion. |

## Reproducibility and scenarios

A session's `scenario_seed` and tick determine the pseudo-random variation. Since session configuration and adaptive decisions also influence generation, reproducing values requires the same virtual state, not just the same scenario name. Scenario options are `normal`, `high_load`, `high_temperature`, `high_vibration`, `high_acoustic`, and `overload`.

## Related control fields

Session properties such as `speed_rpm`, `intensity`, and `pulse_pattern` are virtual control state, not actuator commands. Simulated warning thresholds, predictive warnings, texture target thresholds, component interlocks, and safety-stop results are software rules and do not establish physical operating limits or protection.
